# 4K Wallpaper Desktop V2 功能需求草案

> 状态：Draft 0.3（待产品评审）
> 日期：2026-08-27
> 治理：V1 仍以 `docs/REQUIREMENTS.md` 为实施真源；本草案确认前不授权 V2 代码开发。

## 1. 产品目标

V2 在 V1 的本地优先、多显示器和稳定静态壁纸能力上，升级为可管理、可编排、可扩展的个人壁纸中心。

- 清楚区分在线元数据、在线已下载、本地索引、缺失文件、收藏和集合。
- 建立可复用壁纸集合，为每块显示器配置可解释的切换规则。
- 将多个在线 Provider 聚合为统一资源池，单个 Provider 故障不影响其他在线来源和离线能力。
- 高风险能力可关闭、可降级，不影响静态壁纸主流程。

## 2. 产品与技术边界

继续遵守：Local First、No Required Account、No Self-hosted Server、Provider Independent、Platform Independent Core、Offline Available、Privacy by Default。

技术栈保持：

```text
Tauri 2
Vue 3
TypeScript
Rust Stable
SQLite
```

不得用 Electron、Flutter 或新增 Web 服务替换现有架构。

### V2 Core（正式版必须完成）

1. 图库 2.0。
2. 壁纸集合与批量管理。
3. 自动切换 2.0。
4. Provider 中心与至少一个新增在线 Provider。
5. 静态跨屏拼接。
6. 主题系统。
7. 数据迁移、诊断和生产打包。

### V2 Experimental（通过质量门槛后进入正式版）

1. 动态/视频壁纸。
2. 本地图片内容识别和语义搜索。
3. 自动更新。

### V2 仍不包含

- 用户注册、登录、云同步和自建服务端。
- 壁纸社区、评论、关注、支付。
- 在线插件市场和未经审核的代码插件。
- 遥测、历史上传、日志上传。
- 必须依赖云端 AI 的功能。

## 3. 核心用户场景

1. 从统一搜索和刷新入口同时获取多个已启用图源的结果，再按来源、分类、标签和状态批量整理。
2. 为工作屏和娱乐屏建立不同集合，使用轮询、洗牌或时间规则切换。
3. 将一张超宽静态图片按显示器位置切片，形成连续跨屏效果。
4. 可选启用视频壁纸或本地语义搜索，资源紧张时自动暂停或降级。

## 4. 图库 2.0

### FR-V2-GAL-001 统一图库状态

必须区分：

- 在线元数据：尚未下载的 Provider 资源。
- 在线已下载：原图位于应用数据目录。
- 本地索引：用户文件仍在原目录。
- 暂不可用：可移动磁盘离线或权限暂时丢失。
- 已缺失：文件已确认删除。

UI 不得再用“本地”同时表示 LocalProvider 和在线下载缓存。

### FR-V2-GAL-002 筛选与排序

支持组合筛选：图片名称、Provider、本地/在线/下载状态、分类、标签、分辨率、比例、格式、收藏、黑名单和集合。

支持名称、最新、最近使用、文件大小和随机排序。10,000 条 Metadata 必须分页查询。

### FR-V2-GAL-003 批量管理

多选后支持：

- 加入或移出集合。
- 收藏或取消收藏。
- 标记不喜欢。
- 下载在线原图。
- 删除应用缓存。
- 移除本地索引。
- 重新生成缩略图。

移除本地索引不得删除用户源文件。永久删除源文件不进入 V2 Core。

### FR-V2-GAL-004 增量索引

- 对用户授权目录使用文件监听或增量扫描。
- 识别新增、重命名、移动和删除。
- 可移动磁盘离线时标记暂不可用，不立即删除索引。
- 手动刷新执行完整一致性检查。
- 相同 Hash 提供重复项视图，不自动删除用户文件。

### FR-V2-GAL-005 导入与分享

- 支持拖入单个、多个文件和目录。
- 支持扫描添加目录。
- 支持从剪贴板导入图片或图片 URL，URL 下载前必须确认。
- 在线图片可复制 Provider 来源页链接。
- 本地图片可复制路径或在文件管理器定位，不生成虚假公网链接。

## 5. 壁纸集合

### FR-V2-COL-001 手动集合

用户可创建、重命名、排序和删除集合，并设置名称、说明和封面。删除集合不得删除壁纸或缓存。

### FR-V2-COL-002 智能集合

根据 Provider、分类、标签、分辨率、比例、收藏和下载状态动态生成。规则必须使用版本化结构，不允许保存任意 SQL。

### FR-V2-COL-003 选择反馈

卡片操作必须显示“加入轮换集合”等明确文本或 Tooltip，不得只显示含义不明的 `+`。

## 6. 自动切换 2.0

### FR-V2-ROT-001 来源

每块显示器可选择一个或多个集合、智能来源或最近有效壁纸回退池。

### FR-V2-ROT-002 策略

- 顺序轮询。
- 洗牌队列：一轮内不重复，使用完后重新洗牌。
- 最近未使用优先。
- 加权随机：收藏和分辨率适配度可提高权重。

“下一张壁纸”必须全局可见，并显示来源、集合和选择原因。

### FR-V2-ROT-003 规则

支持固定周期、时间段、工作日/周末、电池模式暂停、全屏应用暂停。睡眠恢复后最多补执行一次，不使用外部 Cron。

### FR-V2-ROT-004 控制与诊断

- 提供上一张、下一张、暂停和恢复。
- 按显示器展示历史和失败原因。
- 可从历史恢复某张壁纸。
- 黑名单、缺失或已移除资源不得被选择。
- 在线下载失败时尝试下一个候选，尝试次数必须有界。

## 7. Provider 中心

### FR-V2-PRO-001 Provider 注册表

Provider 统一声明最新、热门、随机、搜索、分页、分类、API Key、下载、速率限制、健康状态和启用状态。Provider 是内部 Adapter 和资源来源标识，不是用户必须选择的主搜索入口。

### FR-V2-PRO-002 聚合搜索与刷新

- 搜索、发现刷新和在线元数据同步必须查询所有已启用且支持相应能力的 Provider，不设置单一默认在线 Provider。
- LocalProvider、本机 SQLite 元数据和所有已启用在线 Provider 共同组成统一资源池；离线时自动只返回本地可用结果。
- Provider 请求使用有界并发和独立超时。任一来源失败时返回其他来源的部分成功结果，并展示失败来源及可重试状态。
- UI 只提供统一的搜索和刷新动作；Provider 可作为高级筛选、来源署名、启用开关和诊断条件，不得要求用户逐个图源重复搜索或刷新。

### FR-V2-PRO-003 合并、排序与去重

- 各 Provider 的相关度、热门度和时间字段先转换为统一排序模型，再进行公平交错，避免单个大图源占满首屏。
- 聚合分页必须保存各 Provider 独立游标或页码，首页、尾页和指定页跳转不得导致稳定结果重复或遗漏。
- 每次拉取新资源必须在写入统一资源池和返回 UI 之前完成去重，搜索、发现刷新和后台同步不得展示多个图源返回的同一图片。
- 同一 Provider 先使用 `provider + remote_id` 去重；跨 Provider 依次使用规范化原图 URL、已知内容 Hash、原始尺寸与比例、缩略图感知哈希进行识别。
- 缩略图感知哈希只有在比例和尺寸关系相容且相似度超过经测试确定的阈值时才能自动合并。未达到确定阈值的结果标记为“疑似重复”，不得静默删除。
- 原图下载后必须计算 SHA-256；字节不同但仅存在合理缩放、裁剪或重新编码差异时，使用原图感知哈希复核并更新统一内容身份。
- 去重不得为了比对而预先批量下载所有高清原图；拉取阶段只允许使用 Provider 元数据和正常加载的缩略图，原图确认随用户下载或设置壁纸发生。
- 同一内容存在多个来源时只展示一个统一壁纸实体，但必须在 `wallpaper_provider_source` 中保留全部来源、作者、授权、原图地址和来源页。主下载来源优先选择授权清晰、原图分辨率高且当前健康的记录。
- 收藏、不喜欢、黑名单、历史、集合和轮换状态绑定统一壁纸实体。任何来源被判定为同一内容后，已标记“不喜欢”的图片不得通过另一个 Provider 再次出现。

### FR-V2-PRO-004 新增来源

V2 Core 至少增加一个使用官方 API、通过授权条款和稳定性评审的在线 Provider。具体来源在 Phase 0 通过 ADR 确认，禁止用网页抓取替代官方 API。

### FR-V2-PRO-005 密钥、状态与隔离

- API Key 仅保存在本机安全配置中，不写入源码和日志。
- 无 Key Provider 可独立使用。
- 单个 Provider 不可用不得影响 LocalProvider 和其他 Provider。
- 每个 Provider 独立保存启用状态、同步游标、速率限制、最后成功时间和最近错误；不得存在控制全局在线查询的单值 `online_provider`。
- V2 只加载随应用签名发布的内置 Adapter，不实现在线插件市场。

## 8. 静态跨屏拼接

### FR-V2-SPAN-001 布局

根据显示器物理位置、分辨率、系统缩放和方向建立虚拟画布，并保存布局快照。

### FR-V2-SPAN-002 渲染

- 一张源图生成每块显示器对应切片。
- 支持 Fill 和 Fit-to-span。
- 原图保持不变，切片写入 `cache/processed/`。
- 布局变化后重新生成，不沿用错误切片。
- 无法原生跨屏时，由 Platform Adapter 为每屏设置对应切片。

### FR-V2-SPAN-003 降级

任一屏设置失败时记录具体屏幕错误，并允许一键回退到各屏独立壁纸。

## 9. 主题系统

V2 继承 V1 的深色、浅色、跟随系统、自定义配色、渐变和彩虹能力，并扩展为声明式“外观主题包”。

### FR-V2-THE-001 外观形态

主题可声明应用外观形态，包括：

- 标准图片网格。
- 沉浸式大图画廊。
- 紧凑收藏管理。
- 透明/毛玻璃层级（平台支持时启用）。
- 卡片圆角、密度、阴影和动效强度。

外观变化不得隐藏核心功能或改变数据含义。

### FR-V2-THE-002 配色与视觉资源

- 使用统一 Design Token 管理颜色、间距、字体、圆角、阴影和动效。
- 主题可提供声明式渐变、背景纹理和图标映射。
- 必须满足正文、按钮和焦点状态的可读性要求。
- 尊重系统减少动态、增强对比度和浅色/深色偏好。

### FR-V2-THE-003 导航菜单

主题可在以下导航形态中选择：

- 左侧完整导航。
- 左侧紧凑图标导航。
- 顶部导航。
- 底部 Dock 式导航。

路由、权限和功能集合保持一致；主题只决定呈现方式。窗口过窄时必须自动回退到可用布局。

### FR-V2-THE-004 安全边界

- 主题包只能包含经过 Schema 校验的 JSON、CSS Token 和静态资源。
- 禁止主题执行 JavaScript、Rust、Shell 或加载远程脚本。
- 主题不得访问文件系统、网络、历史和 Provider Key。
- V2 Core 只提供内置主题，不实现在线主题市场。
- 任一主题加载失败时回退到 V1 深色主题。

### FR-V2-THE-005 自定义背景图片

- 用户可选择本地图片作为应用界面背景；该图片不作为桌面壁纸，也不得上传到远程服务。
- 应用必须根据窗口尺寸、系统缩放和屏幕 DPI 自动适配，并提供 Fill、Fit、Center 和 Stretch 方式，默认保持图片宽高比。
- 背景图片变更、丢失或无法解码时必须安全回退到当前主题的默认纯色背景。
- 应用必须依据背景亮度自动选择可读文字，必要时增加可配置遮罩；正文、标签、控件和焦点状态均需满足可读性要求。
- 背景图片配置和必要的本地处理缓存只保存在 AppData，不改变主题包的无脚本安全边界。

## 10. 动态/视频壁纸（Experimental）

- 首期只评估本地 MP4/WebM，默认关闭，不自动下载大体积视频。
- 提供帧率、静音和质量上限。
- 全屏、锁屏、睡眠或电池模式自动暂停。
- 暂停时显示静态封面，退出或崩溃后恢复正常桌面。
- Windows 11 x86_64 与 macOS Apple Silicon 分别完成原生 PoC 和资源测试。
- 任一平台未通过时不得宣称跨平台完成。

## 11. 本地智能搜索（Experimental）

- 图片分析、向量和查询默认只在本机处理。
- 不上传图片、向量、关键词和历史。
- 首次启用前展示模型体积、磁盘和内存影响。
- 支持自动标签和自然语言查找，并与普通 Metadata 搜索区分。
- 用户可删除全部模型与索引数据。
- 模型缺失或索引失败时，普通搜索继续可用。
- 模型运行时和格式必须由性能基准 ADR 决定，不直接绑定云 API。

## 12. 自动更新（Experimental）

- 只接受 HTTPS 清单和签名发布包。
- 默认只检查，不静默安装。
- 展示版本、变更摘要、包大小和签名状态。
- 支持跳过版本和关闭检查。
- 更新失败不得影响当前版本。
- 未落实 Windows 代码签名、macOS Developer ID 和 notarization 前不得进入正式版。

provider_sync_state
wallpaper_provider_source
wallpaper_content_identity
wallpaper_file_state

要求：

- 全部使用有序 Migration。
- V1 原地升级后收藏、黑名单、历史、调度和本地目录不得丢失。
- V1 的单值 `online_provider` 必须迁移为 Provider 启用配置；已有 Wallhaven 数据继续保留来源关系，不得重新下载或重复建档。
- `wallpaper_content_identity` 保存规范化 URL、SHA-256、感知哈希、尺寸和去重置信状态；去重合并必须在事务中迁移收藏、历史、集合和轮换引用。
- Migration 失败必须回滚并保留原数据库。
- 大型索引任务不得长时间持有 SQLite 写锁。
- 语义向量存储方案由基准测试 ADR 决定。

## 15. 平台兼容性

| 能力 | Windows 11 x86_64 | macOS Apple Silicon |
|---|---|---|
| 图库、集合、Provider、Scheduler | 必须 | 必须 |
| 静态跨屏拼接 | 必须真机验证 | 必须真机验证 |

## 16. 非功能要求

### 性能

- 10,000 条 Metadata 的名称/标签分页查询目标小于 200ms。
- 5,000 张本地图片增量刷新不得每次重算全部 Hash。
- 静态后台空闲 CPU 目标低于 1%。
- 动态暂停后资源占用应回到接近静态模式。
- UI 列表禁止批量加载原图。

### 稳定性

- Provider、文件监听、AI 和动态任务相互隔离。
- 后台任务失败不得导致应用退出。
- 睡眠、热插拔和虚拟桌面变化后恢复配置。
- 长任务支持取消、进度和有界并发。

### 隐私与安全

- 默认无遥测，不上传图库、历史或日志。
- URL 下载限制协议、大小、超时和格式。
- 外部路径经过授权范围和规范化校验。
- API Key 与签名材料不得进入日志或源码。

## 17. 开发 Phase

### V2 Phase 0：冻结与 PoC

- 冻结 V2 Core 范围。
- 选择新增 Provider 并记录 ADR。
- 完成跨屏、动态壁纸和本地 AI 性能 PoC。
- 确认代码签名和发布渠道。

### V2 Phase 1：数据库与图库 2.0

- Migration、文件状态、增量扫描、组合筛选、批量管理和重复项视图。

### V2 Phase 2：集合

- 手动集合、智能集合规则和批量管理。

### V2 Phase 3：自动切换 2.0

- 洗牌队列、时间/电源/全屏规则、上一张/下一张、选择原因和有界重试。

### V2 Phase 4：Provider 中心

- 注册表、聚合查询、统一分页、公平合并、配置、健康状态、新增正式 Provider、独立限流和错误隔离。

### V2 Phase 5：静态跨屏

- 布局快照、虚拟画布、切片和双平台真机验证。

### V2 Phase 6：主题与交互

- 声明式主题 Schema、外观形态、配色资源、导航布局、可访问性和安全回退。

### V2 Phase 7：实验能力

- 动态壁纸、本地智能搜索、自动更新分别通过门槛后合入。

### V2 Phase 8：稳定与发布

- 数据迁移、长时间 Scheduler、睡眠、热插拔、Windows 升级安装和 macOS 安装签名测试。

## 18. V2 Core 验收标准

- V1 功能无阻断性回归。
- 10,000 条图库数据可分页、组合筛选和批量管理。
- 文件删除、移动和磁盘离线状态正确区分。
- 集合可持久化并被每屏 Scheduler 使用。
- 洗牌队列一轮内不重复。
- “下一张”全局可见并解释来源。
- 一次搜索或刷新可合并所有已启用图源；任一图源失败时仍返回其他图源和本地结果。
- 多个图源返回同一图片时，搜索、刷新和分页结果只出现一个统一资源；下载后发现重复也必须安全合并且不丢失用户状态和来源授权。
- 已标记不喜欢或黑名单的内容不得因更换 Provider、URL、尺寸或编码后重新出现。
- 聚合结果不得因单一图源数据量更大而长期垄断首屏。
- 新 Provider 故障不影响 Wallhaven、LocalProvider 和离线切换。
- 静态跨屏在两个目标平台真机验证。
- 内置 V2 主题可切换外观和导航形态，核心路由与功能入口保持完整。
- V1 数据升级后收藏、黑名单、历史和配置保持一致。
- `cargo fmt`、`cargo check`、`cargo test`、前端类型检查和生产构建通过。

## 19. 风险与控制

| 风险 | 影响 | 控制 |
|---|---|---|
| 动态壁纸依赖非标准桌面宿主 | 系统更新后失效 | 独立 Adapter、实验开关、静态回退 |
| 本地 AI 模型过大 | 安装包和内存增加 | 可选下载、延迟加载、体积门槛 |
| Provider API 或条款变化 | 在线功能不可用 | 官方 API ADR、健康状态、故障隔离 |
| 文件事件丢失或风暴 | 索引不一致或高 CPU | 防抖、增量队列、周期一致性检查 |
| 跨屏布局复杂 | 切片错位 | 布局快照、预览、双平台真机测试 |
| 更新签名链不完整 | 安全或安装失败 | 保持 Experimental，不允许强制更新 |

## 20. Phase 0 待决策项

1. 动态壁纸是否必须进入 V2 正式版。
2. 首批聚合 Provider 的具体组合、默认启用状态及 API Key 策略。
3. 是否允许额外下载本地 AI 模型及模型体积上限。
4. 跨屏是否支持任意错位布局，还是首版只支持常见矩形排列。
5. 是否具备代码签名与稳定更新渠道。
6. 是否允许用户显式永久删除 LocalProvider 源文件。
7. Windows 与 macOS 是否要求同日同功能发布。
